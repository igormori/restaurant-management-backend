## T5 — Member grids: storage, lookup, audited changes
| Field | Value |
|---|---|
| Expected context | No per-location access is stored. Roles (T4) and memberships (T3) exist. Audit entries go through `IAuditLog` (`src/RestaurantManagement.Shared/Services/AuditLog/`), with organization, user and time stamped from the token, as `LocationService.RecordStatusChangeAsync` does. No endpoint changes a grid in this slice (slice 2 adds it and who may call it) |
| Expected result | Two organization tables: member levels (user, location, module, level; one row per cell; None means no row) and member role labels (user, location, role; labels point to roles, so a rename shows everywhere). Identity implements `IMemberAccessLookup`, read from storage on every call: the grid holds the Owner flag and only that organization's cells, and a non-member gets no cells; it also answers user exists and the user's organization IDs (identifiers). An Identity service (not a Shared contract) sets a member's access at one location from chosen roles plus changed cells: roles merged with the higher level per cell, changed cells applied, final levels and labels stored. It refuses the Owner (403, nothing stored) and answers not found for a non-member, or a role or location of another organization. One `member.access_changed` entry per change, with labels and levels before and after; none when nothing changed; a failed audit write keeps the change and logs the error. A reader returns, per location, the current role names and levels |
| Outcome | #5 (the Owner cannot be lowered), #7 (a new Admin has no cells), #8 (Waiter + Cashier give the higher of each), #9 (changing a role's default levels leaves stored levels; a rename changes labels only), #12, #13. Verified by Identity unit tests and a PostgreSQL test in `tests/RestaurantManagement.Web.Tests/Identity/` |
| Files | `add` level and label entities, `Services/MemberAccessLookup.cs`, the access service and reader, migration · `change` `Data/IdentityDbContext.cs` (all under `src/RestaurantManagement.Modules.Identity/`) · `change` `src/RestaurantManagement.Web/Program.cs` (registration) · `add` tests · `change` `docs/security/identity-matrix.md` |
