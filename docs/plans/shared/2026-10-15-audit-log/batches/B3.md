# Batch B3 — Audit Log

**Plan:** docs/plans/shared/2026-10-15-audit-log/plan.md   **Tasks:** T3, T4

Both tasks add `IAuditLog` (from Shared) to an Organization service constructor. Existing unit tests that build `OrganizationService` or `LocationService` must pass a substitute `IAuditLog`; the tester updates them before Gate 2. An entry is recorded only after the service's own save succeeds. If recording throws, the change stays, the error is logged and the request still succeeds (the user chose this; the outbox follow-up is in `backlog/improvements/2026-10-16-audit-entries-through-outbox.md`).

## T4 — Record location status changes
| Field | Value |
|---|---|
| Expected context | `LocationService.EditLocationAsync` may change `Status`; `DeleteLocationAsync` is a soft delete that sets `Closed` (`src/RestaurantManagement.Modules.Organization/Services/LocationService.cs`). Statuses: Active, Closed, TemporarilyClosed, UnderConstruction. The tenant filter already returns not found for another organization's location |
| Expected result | When a location's status actually changes (edit or delete), one `location status changed` entry is recorded. It has the location set, changed item = location and its ID, and before and after = status names (e.g. `Active` to `TemporarilyClosed`). No entry when the status is unchanged (edit without a status change, or delete of an already Closed location) or when the request is rejected |
| Outcome | Rule 2 (location status changed is logged); verified by reading the entry through T2's endpoint |
| Files | `change` `src/RestaurantManagement.Modules.Organization/Services/LocationService.cs` · `add`/`change` tests in `tests/RestaurantManagement.Modules.Organization.Tests/` and one end-to-end test in `tests/RestaurantManagement.Web.Tests/` |
