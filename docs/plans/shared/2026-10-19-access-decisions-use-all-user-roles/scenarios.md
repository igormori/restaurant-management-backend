## Existing tests updated
These tests substituted the removed single-role lookup. They now return the same one role through the new all-assignments lookup (a user with no role returns an empty list). Their expectations are unchanged, so single-role behaviour keeps its meaning (Outcome 6). Until T3 and T4 are built the old service code still asks the old method, so these tests return "no role": the refusal ones pass for the wrong reason and the allow ones fail.

- `tests/RestaurantManagement.Modules.Menu.Tests/`: `MenuServiceTests`, `MenuServiceRoleAccessTests`, `MenuCategoryServiceTests`, `MenuCategoryOrderTests`, `MenuLocationLinkTests`
- `tests/RestaurantManagement.Modules.Organization.Tests/`: `LocationServiceTests`, `LocationFieldsTests`, `LocationServiceAuditTests`, `LocationListTests`, `OrganizationServiceEditTests`, `OrganizationServiceAuditTests`

## Notes for Gate 2
- **Refusal tests that pass before the implementation (decided by the user: option A).** Scenarios 13, 14, 15, 18, 19, 25, 26, 28, 29, 31, 32 and the existing single-role refusal tests pass now because the old service asks `GetRoleAsync`, gets no role and refuses. This is expected: the old code also refuses these cases. `GetRoleAsync` is not stubbed in tests, because T5 removes it and tests are read-only after Gate 2. Each refusal is paired with an allow test that uses the same lookup setup and fails today (12, 17, 23, 24, 27, 30, 33), so a "refuse everyone" implementation fails the suite and the allow tests prove the change is needed.
- **Same check, one representative test.** Menu create/delete share one check per service (`CheckUserPermission`), as do menu edit, link and unlink, and category read, update and delete. Scenarios 12-19 test create and delete on that check; repeating them per action would be padding. Location close has its own allow (38) and refusal (26) tests because it uses the location question.
- **Cross-tenant 404 (another organization's menu, category or location)** is not changed by this plan and is already covered by existing tests: `MenuTenantEndpointTests.MenuById_MenuOfAnotherOrganization_ReturnsNotFoundAndLeavesItUnchanged` (M7), `MenuTenantEndpointTests.MenuCategoryById_CategoryOfAnotherOrganization_ReturnsNotFoundAndLeavesItUnchanged` (M8), `OrganizationTenantEndpointTests.LocationById_LocationOfAnotherOrganization_Returns...` (OR14). They must stay green.
- **Matrix status.** M28 is ✅ (its only test is a passing guard). OR34 stays ❌: two of its three tests are refusals that pass for the wrong reason until T4.
