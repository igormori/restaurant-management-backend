## T7 — X-Location-Id check middleware
| Field | Value |
|---|---|
| Expected context | Pipeline in `Program.cs`: exception middleware, authentication, authorization, controllers. `ExceptionHandlingMiddleware` lives in `Shared/Middleware` and turns `BusinessException` into a localized status. Nothing reads X-Location-Id today. The middleware may use only Shared contracts (`ITenantContext`, `ICurrentUser`, `IOrganizationLookup`, `IUserRoleLookup`) |
| Expected result | For a signed-in request carrying X-Location-Id: not a valid ID gives 400; no organization in the token gives 403; location not in the token's organization (unknown, or another organization's) gives 403; no role assignment for that location or for all locations gives 403 (Rule 4). Otherwise the location is stored in the T1 holder so location-owned reads are limited to it. No header: no location limit. Anonymous requests ignore the header. Registered after authentication, before controllers. Messages are localized (en, pt) |
| Outcome | #3: user assigned only to Batel sending Mercado Municipal gets 403. #4: user with an all-locations role gets 200 for any location of their organization. #5: sending another organization's location gets 403. Verified by endpoint tests on `GET /api/menus` (from T3) |
