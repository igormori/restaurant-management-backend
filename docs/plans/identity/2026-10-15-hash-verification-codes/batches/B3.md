## T3 — Store and check codes as fingerprints
| Field | Value |
|---|---|
| Expected context | `RegistrationService` and `VerificationService` save `UserVerificationCode.Code` as readable text, and `VerifyEmailAsync` compares it with `!=`. Resend already marks all earlier unused codes as used (Rule 3), and the attempt limit and lockout already work (Rule 5). Keep both, along with the uniform 401 and the unknown-email path in the Identity `CLAUDE.md`. Existing tests seed readable codes, so they must seed fingerprints instead |
| Expected result | The entity property `Code` becomes `CodeHash` (column `code_hash`). Registration and resend save only the fingerprint, and the readable code goes only to the email. Verify loads the newest unused, unexpired code and calls the hasher's match. The unknown-email path still does the same work. Failed attempts, lockout, expiry, cooldown and "only the newest code works" behave as before. Migration: rename the column only (the backfill is in T4) |
| Outcome | #1: the stored value differs from the emailed code (after registration and after resend) · #2: a valid code verifies and is marked used · #3: a wrong code returns 401 and the attempt count rises by 1 · #4: once locked, any code returns 423 · #5: expired or used codes are rejected · #6: after a resend the first code is rejected and the newest is accepted |
