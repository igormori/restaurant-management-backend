## T1 — Token roles only for the organization in the token
| Field | Value |
|---|---|
| Expected context | `AccessTokenFactory.Create(user, selectedOrganizationId)` builds every access token. With an organization chosen it adds only that organization's roles; with none chosen it adds all roles of all organizations, and adds the organization claim only when the user has exactly one organization. `SessionService.LoginAsync` always passes no organization; `RefreshTokenAsync` passes the refresh token's organization (none after a plain login); `SelectOrganizationAsync` passes the chosen one. Keep the factory's single responsibility; no change to `SessionService`, the response models or the organization list returned at sign-in. Access is decided by permissions; `MenuController` still has `[Authorize(Roles = "Owner,Admin")]` as a first filter (Menu `CLAUDE.md`), which is what Outcome 2 exercises. |
| Expected result | The token's roles always match its organization claim: chosen organization → its roles; no choice and exactly one organization → that organization and its roles; no choice and 0 or 2+ organizations → no organization claim and no role claims. Sign-in still lists the active organizations to choose from (Rule 4). |
