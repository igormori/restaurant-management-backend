## T4 — List, read and create roles
| Field | Value |
|---|---|
| Expected context | Roles (`OrganizationRole`, `OrganizationRoleLevel`) are tenant entities filtered by the token organization. A None level is not stored. Invitations and grid edits pick roles by name through `MemberGridBuilder`, so a new role is usable at once. Follow `MemberAccessService` and `InvitationService`: organization from the token only, level names parsed with `InvitationGrids.ParseLevels` (unknown name is 400), and an audit write that fails is logged without undoing the change. Catch the unique index violation the way `RegistrationService` does. Controllers hold no logic |
| Expected result | `GET api/roles` lists the token organization's roles with their levels per module. `GET api/roles/{roleId}` returns one role, or 404 for an unknown role or one of another organization. Both are open to any member with access (Owner or any cell). `POST api/roles` creates a role from a name and levels. A missing module means None. The name is trimmed, and it is refused with 400 and nothing saved when it is empty, over 100 characters, "Owner" in any letter case, or already used in the organization in any letter case (a lost race gets the same 400). The T3 rule runs before any write. One `role.created` entry records who, when and the name and levels after |

## T5 — Edit a role's levels and rename it
| Field | Value |
|---|---|
| Expected context | Member grids store their own levels, so role defaults never touch them. Member labels point to the role by ID, so a rename shows in every label with no extra write (identity matrix T42). The unique index on (role, module) means level rows are updated in place, not deleted and re-added in one save (see `MemberAccessService.StoreLevelsAsync`). Same validation, rule and audit pattern as T4 |
| Expected result | `PUT api/roles/{roleId}/levels` replaces the role's default levels. Existing grids are unchanged, and later invitations and grid edits use the new levels. `PUT api/roles/{roleId}/name` renames the role, and every holder's label shows the new name. A role's own name in another letter case is allowed. Both return 404 for an unknown role or one of another organization, and 400 for the T4 name and level refusals. The T3 rule gets the role's current levels, so a role above the caller's cap is refused for both. Audit: `role.levels_changed` with the levels before and after, `role.renamed` with the names before and after, and no entry when nothing changed |
