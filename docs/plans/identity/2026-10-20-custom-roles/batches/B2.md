## T3 — Who may manage roles, and the cap
| Field | Value |
|---|---|
| Expected context | `MemberDelegationRules` checks member grid changes per location: Members = Manage, then a cap per location and module. Roles have no location, so the spec applies the rule for actions not tied to one location: the caller's level at every non-closed location (`IOrganizationLookup.GetNonClosedLocationIdsAsync`, the same set `AccessGuard.RequireAtEveryLocationAsync` uses). The Owner is the membership flag and is never capped. Never check a role name in code. Reuse `AccessDenied` and `CannotGrantAboveOwnLevel` |
| Expected result | One rules class (with interface) runs before any write. It takes the role's current levels (none for a create) and the proposed levels (none for a rename). Refusals are 403: no organization in the token, not a member, or a non-Owner without Members = Manage at every non-closed location (`AccessDenied`). Also 403 when any current or proposed level in a module is above the caller's level for that module at every non-closed location (`CannotGrantAboveOwnLevel`). A missing cell counts as None. An organization with no non-closed location refuses every non-Owner. The Owner passes everything |
| Outcome | #5 (cap on create), #6 (a role above the cap cannot be edited or renamed), #7 (Members = Manage required). Verified by Identity unit tests |
| Files | `add` rules class and interface in `src/RestaurantManagement.Modules.Identity/Services/` · `change` `src/RestaurantManagement.Web/Program.cs` (registration) · `add` tests in `tests/RestaurantManagement.Modules.Identity.Tests/` · `change` `docs/security/identity-matrix.md` |
| Modules | Identity (registration in Web) |
| Flags | Security: new authorization rule |
| DoD | Tests written and passing · Owner passes any levels · Admin with Members = Manage everywhere passes levels at or below her own · Admin refused when one proposed level is above her own in one module · Admin refused for a rename of a role whose current level is above her own · Members = Manage at only one of two non-closed locations is refused · a closed location's missing cell does not lower the cap · one rejection test per role that lacks Members = Manage (Manager, Cashier, Waiter, Kitchen) · non-Owner refused when no location is non-closed · `docs/security/identity-matrix.md` rows added or changed and ✅ with their tests; `python3 .claude/scripts/check-security-matrices.py` passes |
