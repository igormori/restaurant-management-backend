## T2 — Role assignment needs an organization; no duplicates
| Field | Value |
|---|---|
| Expected context | `UserRole` (Identity `Entities/UserRole.cs`) has nullable `OrganizationId` and `LocationId`, and no unique index. Configuration is in `IdentityDbContext.OnModelCreating`. `OrganizationMembership`, `UserRoleLookup` and `AccessTokenFactory` filter or unwrap the nullable organization. `UserRoleAssigner` always passes an organization. The table is empty in every environment (spec decision), so no data backfill. Follow `.claude/skills/ef-migration/SKILL.md`. Organization is another module: ID only, no foreign key. |
| Expected result | `organization_id` is NOT NULL. A unique index on (user, organization, location, role) uses `NULLS NOT DISTINCT`, so a second "all locations" row (empty location) for the same user, organization and role is rejected by PostgreSQL. Different location, role or organization is still allowed. Identity code no longer handles a missing organization. |
| Outcome | #5 — inserting a role row with no organization fails with a PostgreSQL not-null error · #4 — inserting a second identical row for Org A with no location fails with a unique-violation error |
