## T3 — Permission policies and private-by-default endpoints
| Field | Value |
|---|---|
| Expected context | `src/RestaurantManagement.Web/Program.cs` sets up JWT (JSON Web Token) bearer auth with JSON bodies for 401 (`OnChallenge`) and 403 (`OnForbidden`), but no authorization policies; endpoints without `[Authorize]` are open. `AuthController` endpoints register, login, refresh, logout, verify, resend-verification carry no attribute. The access token holds role claims for the selected organization plus an `AppClaimTypes.OrganizationId` claim; with several organizations and none selected it holds roles from all of them and no organization claim. No current endpoint needs members.manage. |
| Expected result | One policy per permission, named by the permission string, met when the token has an organization claim and at least one role claim that `RolePermissions` grants that permission; otherwise 403. A fallback policy requires a signed-in user on every endpoint that declares nothing; anonymous gets 401. The six auth endpoints above are marked public explicitly and keep working without a token. Existing `[Authorize]` and `[Authorize(Roles=...)]` endpoints behave as before. |
| Outcome | #2 — a Manager token calling an endpoint that needs members.manage gets 403 · #3 — an anonymous call to an endpoint with no access declaration gets 401 |
