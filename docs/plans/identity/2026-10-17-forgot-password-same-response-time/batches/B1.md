## T1 — Pending reset request table
| Field | Value |
|---|---|
| Expected context | Identity has no queue today; `PasswordResetService.RequestResetCodeAsync` does all the work during the request. Tables live in `IdentityDbContext`, configured in `OnModelCreating`. Migrations follow `.claude/skills/ef-migration/SKILL.md`. The database holds no real data (root `CLAUDE.md`), so no backfill. A pending request has no user yet, so the table has no foreign key to `users` |
| Expected result | A new `password_reset_requests` table holds one row per forgot-password request: id, email as typed, created at, number of send attempts, next attempt time, claimed until (so two app instances never handle the same row), and failed at (set after the last retry). An index on next attempt time lets the processor find due rows |
