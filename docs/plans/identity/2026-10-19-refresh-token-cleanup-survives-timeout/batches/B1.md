## T1 — Cleanup worker tells a shutdown apart from a timeout
| Field | Value |
|---|---|
| Expected context | `RefreshTokenCleanupWorker` (a `BackgroundService`: .NET's base class for long-running jobs) purges at startup, then every day on a `PeriodicTimer`. Its catch filter skips every `OperationCanceledException`, so a database or driver timeout (`TaskCanceledException`) escapes `ExecuteAsync` and, under the default host setting, stops the application. Follow the filter in `PasswordResetEmailWorker.RunPassAsync` (catch when the stopping token is not cancelled) and the test style of `PasswordResetEmailWorkerCancellationTests` (NSubstitute substitute that throws, `CapturingLogger`). Keep the 1-day interval and the existing log messages; add no public method only for tests. |
| Expected result | A cancellation or timeout while the stopping token is not cancelled is logged as an error ("Refresh token cleanup failed") and the worker keeps waiting for the next daily run. A cancellation once shutdown is requested ends the worker with no error log. Ordinary failures behave as today. |
| Outcome | #1: with the cleanup service throwing `TaskCanceledException` and no shutdown, an error is logged and the worker's running task (`ExecuteTask`) has not completed. #2: with shutdown requested during a run, the worker's task ends and no error is logged. #3: both tests named in a new Identity matrix row. Tests drive the worker through `StartAsync` / `StopAsync` (public `BackgroundService` methods). |
