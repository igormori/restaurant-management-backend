## Existing tests moved to the new sign-in API (no new scenario)
The signatures of sign-in, refresh and organization selection change in T3, and the old `User` token fields disappear in T5. Test files are read-only after Gate 2, so these existing tests were rewritten now to call the new methods: device info goes in, a session result comes out, and the token comes from the result instead of email + token. **No assertion was removed or loosened.** The only expectation change is the corrected message key `InvalidOrExpiredToken` (previously the misspelled `InvlideOrExpiredToken`), now checked in scenarios 32–34. Until T3 is done they fail with `NotImplementedException`, or with a 204 instead of a 200 at the HTTP level.
